The source reference and design target are the current desktop FlClash UI. “Implemented” means there is working native code, not that every animation or platform behavior has been verified against the Flutter app.

## Still needed for complete 1:1 parity

- Extend the pinned Flutter widget comparisons beyond the current proxy list/tab, dashboard, appearance, shortcut, IP-details, and service-sheet references. Check the other modals, keyboard focus, reduced motion, screen readers, and locale text overflow. The native and Flutter snapshots still differ in several controls and content details.
- Finish floating-navigation hover/parallax, visibility transitions and real desktop focus behavior. Optional native glass now renders, but both saved quality modes share MyGo's material: source frosting/refraction/ultra warp and hardware-GPU parity remain unimplemented. Glass references exercise the source shader-unsupported fallback, not its GPU shader.
- Finish sheet content-fling inertia, control-started/reversed-scroller arbitration, nested-page transitions and source stacked scaling/peek. Side enter/exit, bottom presentation springs, header/content-edge dragging, wheel latching, cancellation and explicit profile-grid refitting are implemented. Footer preservation currently shrinks the body instead of lifting only the footer; general fit-content remeasurement remains incomplete. Memory/service/quality sheets still use their older immediate presentation.
- Reproduce every specialized preset, multi-select, quick-action, custom-icon, schema and per-rule target form. Nested data editing, profile MatchTarget and the searchable font picker work, but Standard/Script Extend separation, main-tab draft-discard guarding, some context-menu details and source loading/search illustrations/transitions still differ.
- Complete remaining dashboard skeleton/empty/editor-presence/drag transitions, mode/takeover/service/table layouts, extreme-width header capping and LAN's active decoration. Wide status/traffic/profile/LAN geometry and shared start-control motion now have source-derived checks. Shared outbound caching covers the implemented consumers, not every original generic RoutedProbe scheduler behavior.
- Validate Wi-Fi SSID APIs on real desktops and implement macOS/Windows permission prompts/settings flows. Polling is read-only and safe mode performs no SSID calls; monitoring is not yet the source's full connectivity-event subscription.
- Finish resource-wide remote-rule scheduling/editor flows and visual comparisons. Captured-client remote sync, staged compilation/atomic replacement, bulk errors and global subscription metadata dialogs are implemented; metadata/source files survive native backup.
- Compare migrated data against real archives from older Drift schema versions. The explicit Flutter export passed four original parser/restore tests on a synthetic current-schema fixture, including compatible/override/profiles-only restoration. Unsupported native layouts fail explicitly rather than silently losing data; retain a native backup. This is not all-format or older-archive parity.
- Extend the cross-runtime script corpus beyond the current language, promise, exception, timeout, isolation, and memory-limit cases. The engine source now matches upstream; Wasm/native stack behavior and host-dependent APIs still need comparison.
- Validate real system proxy and TUN takeover/restoration on macOS, Windows, GNOME, KDE, and different network configurations. The macOS and Windows implementations have been cross-compiled, not run in this Linux workspace.
- Sign/notarize and exercise packaged installers, protocol registration, startup, sleep/resume, tray behavior, and privileged startup on real desktops. Current artifacts are unsigned development archives. Auto-update delivery is not configured for this new private repository.

The additional glass, font, QR, morph and backup references used the available Flutter 3.47.5 SDK; the source workflow pins 3.47.6. This mismatch is recorded in their fixtures/docs and remains a verification gap. Original references already committed by the previous agent are unchanged.

Mobile packaging and Android-only UI/integrations are intentionally out of scope.
